# Подготовка Google Диска, Яндекс Диска и Яндекс ID

Дата: 10 октября 2026. Статус: Google OAuth-клиент зарегистрирован, Google Drive API включён; браузерная передача опубликована в проверочном режиме только для владельца. Реальное согласие на Диск и сохранение ещё не проверены. Яндекс пока не подключён.

## Что пользователь разрешил

Добавить необязательное сохранение на Google Диск и Яндекс Диск с сайта, затем согласовать этот выбор с Windows и Telegram. По возможности добавить Яндекс ID как способ входа в тот же VideoGrabber-аккаунт. Подготовить регистрацию приложений в аккаунтах владельца. Медиа не передаются на VPS.

## Проверка аккаунтов

- Из-за лимита новых Google Cloud проектов использован разрешённый владельцем `My First Project` (`poetic-glass-472517-n5`). Создан отдельный Web OAuth-клиент `VideoGrabber Drive Web`, разрешён только текущий HTTPS origin сайта. Настроен scope `drive.file`, сохранение прав подтверждено интерфейсом Google. Google Drive API имеет статус Enabled. Приложение External, режим Testing; массовый доступ для клиентов пока не включён. Существующие MOST Control/Hermes credentials в других проектах не изменялись.
- Первый неиспользованный секрет Google после попадания в диагностический вывод заменён с отдельного разрешения владельца. Прежний имеет статус Disabled. Новый секрет не используется браузерным token model и не записан в репозиторий. Не публиковать значения секретов и диагностические снимки их полей.
- В тестовую аудиторию добавлен указанный владельцем аккаунт; в Branding сохранены ссылки главной страницы, условий и конфиденциальности. Настройки Google подтверждены интерфейсом. Переход в Production не выполнялся.
- `https://oauth.yandex.ru/` в браузере вернул `ERR_CONNECTION_TIMED_OUT`. Авторизация и регистрация Яндекса не выполнены. Сетевые настройки компьютера не менялись.

## Три отдельные регистрации

| Назначение | Имя приложения | Права и настройки |
|---|---|---|
| Google Диск | VideoGrabber Drive | Web OAuth client, JavaScript origin `https://videograbber.srv1902378.hstgr.cloud`, Drive API, scope `https://www.googleapis.com/auth/drive.file` |
| Вход через Яндекс | VideoGrabber | Тип «Приложение для авторизации», сведения об ID и email; без разрешений на Диск |
| Яндекс Диск | VideoGrabber Disk | Тип «Приложение для доступа к API», сначала проверить достаточность разрешения на папку приложения; без прав удаления и без login-scopes |

Для Google официальный браузерный token model не требует служебного API-ключа или хранения refresh-токена на VPS. Пользователь сам открывает окно согласия, выдаётся короткоживущий access token. Не хранить его в localStorage, телеметрии или обычной конфигурации аккаунта.

OAuth-клиент и пользовательский токен — разные вещи. Пользователь не создаёт API-приложение для каждой загрузки. Приложение регистрирует владелец один раз; каждый клиент разрешает доступ к собственному диску. Вход через Google/Яндекс сам по себе не разрешает запись на Диск.

Яндекс разделяет приложения авторизации и доступа к API: API-приложению нельзя назначить права группы login. Поэтому одна смешанная регистрация для входа и Диска не подходит.

Callback для Яндекс ID нужно взять из фактически выбранного потока авторизации, а не выдумывать адрес. Текущий код использует Supabase. Предпочтительный путь — custom OAuth provider `custom:yandex`, если установленная версия Supabase Auth поддерживает его. Документация self-hosted требует Auth v2.196.0 или новее; актуальную установленную версию ещё нужно проверить. Обновление Auth является отдельным изменением инфраструктуры и в эту подготовку не входит.

Для Яндекс Диска предлагаемый callback `/cloud/yandex/callback` пока не реализован и не должен регистрироваться как действующий endpoint. Сначала реализовать и проверить одноразовый state, возврат только на разрешённые адреса, обмен кода и защищённое хранение токенов. Секрет OAuth-приложения не включать в сайт или Windows EXE. Регистрация credentials и выдача доступа требуют подтверждения перед завершающим действием.

## Передача файлов

### Реализованный локальный вариант Google

`/v1/cloud/config` требует входа и отдаёт только публичный client ID. `VG_CLOUD_GOOGLE_ENABLED=false` по умолчанию; `VG_CLOUD_GOOGLE_OWNER_ONLY=true` ограничивает подготовительный показ владельцем. Серверный код развёрнут на текущем VPS; в отдельной конфигурации проверки включён только для owner_admin. Anonymous получает 401; остальные роли остаются закрыты. Основная база и существующий режим исполнения сохранены.

`google-drive.js` получает короткий токен через Google Identity Services, держит его только в памяти вкладки и связывает с текущим VideoGrabber AccountId. При выходе или смене аккаунта токен сбрасывается, текущая передача отменяется. Пользователь отдельно выбирает свой Google-аккаунт; диск владельца сервиса не применяется как общий.

Квота проверяется через `about.get`; числовые строки int64 читаются без потери точности. Готовый HTTPS MP4/WebM с известным размером читается по CORS и отправляется в новую папку/файл VideoGrabber частями по 8 МиБ. Адрес upload-сессии проверяется; токен Google не отправляется источнику. Проверяются длина, Content-Type, ответы частей, итоговый ID и размер. Существующие файлы не перезаписываются и не публикуются. Есть прогресс и отмена; автоматическое продолжение после обрыва ещё не реализовано.

Опция «Также открыть файл для сохранения на компьютер» показывает ссылку после успешной облачной передачи. Она не означает автоматическую запись в произвольную папку компьютера.

Проверки: 9 браузерных тестов передачи (квота, точность, изоляция аккаунтов и токенов, ограниченный буфер, повреждённый поток, недопустимый upload URL, смена аккаунта во время запроса и передачи), проверка доступности кнопки при уже загруженной библиотеке Google, 7 серверных случаев включения/ограничения конфигурации, включая отличие роли сессии от роли общего аккаунта и блокировку аккаунта. Реальный вход на сайте через Google подтвердил прежний owner_admin аккаунт, связь с Telegram и наличие Google Диска в выборе сохранения. При проверке выявлена ошибка ограничения preview: роль бралась из JWT, а не общего аккаунта. Исправление использует IAccountStore и добавляет ограничение частоты запросов; реальные проверки после обновления фиксируются отдельно. Само согласие на Диск, CORS конкретного источника и файл на пользовательском Диске ещё не проверены. HLS-страница Rutube не превращается в MP4 от подключения Диска: требуется отдельная обработка.

1. В кабинете: «Куда сохранить → На компьютер / Google Диск / Яндекс Диск». Облачные варианты показываются только после рабочего подключения; неподключённые режимы не выдаются за готовые.
2. Google: браузер читает совместимый прямой файл с источника по CORS и отправляет его в Диск resumable-загрузкой. Папка VideoGrabber, уникальные имена, без перезаписи существующих файлов. Перед загрузкой проверить доступность байтов, размер, права, место и тип файла. Ограниченный буфер, отмена и прогресс; вся запись видео остаётся вне VPS.
3. Яндекс: проверить импорт готового публичного URL силами Диска с последующей проверкой статуса операции. Если прав папки приложения недостаточно, сначала объяснить и согласовать более широкие права. Импорт страницы или HLS не выдавать за готовое видео.
4. Закрытые курсы, объединение дорожек и MP3: обработка на Windows, затем облачная передача с этого компьютера. Сайт не обещает универсальное сохранение любого курса без локального исполнителя.
5. Telegram/Mini App: подключение через защищённую страницу в системном браузере, возврат в общий аккаунт. Для браузерной передачи требуется открытая страница; для Яндекс URL-import — статус и уведомление результата. Само подключение облака не отправляет видео в Telegram.

## Общий аккаунт

Сейчас `SupabaseAuthService.ParseVerifiedIdentity` и `AccountEligibility.CanUseProtectedDownloads` разрешают Google/email. Нельзя просто добавить кнопку Яндекса: нужно проверить идентификатор и доверенного issuer/provider, выдачу сессии, загрузки, привязку Telegram и Windows. Не объединять аккаунты по произвольному email из профиля; привязка к существующему аккаунту требует подтверждённого входа. Тариф, бонусы и история принадлежат VideoGrabber AccountId, а не отдельному облачному подключению.

## Вместимость и масштабирование

Это многопользовательская функция. OAuth-приложение общее, но токены, квота, папка и загрузки принадлежат конкретному клиенту. Диск владельца VideoGrabber не используется как общее хранилище. Вход в Диск другого аккаунта явно показывает, какой аккаунт выбран; смена VideoGrabber-аккаунта сбрасывает браузерные credentials.

- Google: `about.get(fields=storageQuota,user,maxUploadSize)`. Свободно = limit − usage, а не limit − usageInDrive: место также используют другие Google-сервисы. Для pooled storage показать ограничение организации; отсутствие limit не подменять нулём. Байтные int64 читаются как BigInt/проверенные целые, без потери точности Number.
- Яндекс: запрос информации о Диске, total_space и used_space. Точный доступ к квоте при выбранном минимальном scope подтверждается авторизованной проверкой. Отсутствие доступа/ответа означает «Не удалось проверить место», а не «Достаточно места».
- До начала: определить размер файла или сумму материалов курса, сравнить со свободным местом и максимальным размером одного файла. Если точный размер недоступен, показывать оценку и предупреждение о неполной проверке. Проверять квоту снова перед записью: другие устройства тоже расходуют место.
- В процессе: учитывать одновременно выполняемые собственные передачи и уже сохранённые файлы курса; не резервировать место в облаке только на основании собственной базы. Финальный ответ провайдера остаётся авторитетным при quota exceeded. При частичном успехе сохранять manifest и предлагать повтор оставшихся материалов, а не скачивать всё заново.
- Запросы квоты кэшировать коротко в рамках пользователя, объединять параллельные запросы, делать ограниченные повторы с Retry-After. Масштабирование API-квот OAuth-проекта отделено от вместимости личных дисков. Не покупать расширение квот автоматически.

В интерфейсе: «Свободно 12 ГБ · Нужно 3 ГБ», «Недостаточно места — требуется ещё 2 ГБ», кнопки «Обновить», «Открыть Диск», «Увеличить место». Значения только из реального аккаунта, без выдуманных гигабайтов.

## Покупка места и партнёрские ссылки

У Яндекс 360 есть официальная реферальная программа: https://360.yandex.ru/partners/ и https://yandex.ru/support/360-distr/ru/. Регистрация площадки, модерация и договор отдельны от OAuth Диска. Договор/покупки не оформлялись. После получения настоящей ссылки её можно настроить для сайта, Mini App и Windows; рядом ясно указать партнёрский характер перехода. Не придумывать скидки или выдавать нашу рефералку VideoGrabber за бонусы облака.

Обычная партнёрская программа Google One для покупки только дискового пространства текущим поиском не подтверждена. Пока использовать обычную официальную ссылку тарифов Google One; не подменять её AI-подпиской или семейным приглашением. Ссылку показывать только для выбранного провайдера и аккаунта; покупку клиент совершает у провайдера самостоятельно. Условия и доступность покупки проверяются по региону клиента на сайте провайдера.

## Приёмка до публикации

- Реальный вход/отказ в согласии/истечение/отзыв доступа каждого провайдера.
- Собственный маленький MP4, большой файл, источник без CORS, недостаток места, отмена, закрытие вкладки, повтор после обрыва.
- Файл действительно открывается в личном Диске, правильное название и размер; нет автоматического публичного sharing, удаления или overwrite.
- Чужой аккаунт не может использовать подключение, callback не принимает повторный state или внешний return URL.
- Перенос на будущий домен: разрешённые origins/callback добавлены у каждого провайдера, старые подключения и учётная запись сохранены.
