# Канал обновлений Windows и перенос сайта

Версия: preview.63. Владелец подтвердил создание ключа и выпуск 2026-10-09. Private RSA3072 создан в защищённой папке VPS вне Git/API, public pin включён в Core, резервная копия вне VPS защищена Windows DPAPI. Публикация каталога/пакетов и проверка установленного клиента фиксируются в отчёте выпуска. Фактического нового домена пока нет.

## Для пользователя

Приложение проверяет новые версии при запуске и раз в сутки, пока открыто. В «Информации» есть ручная проверка. Уведомление предлагает «Обновить» или «Позже». Обновление скачивается анонимно и становится готовым только после проверки подписи каталога, размера и SHA-256 файла. Установщик не запускается автоматически: пользователь завершает работу, закрывает приложение и запускает его из открытой папки. Настройки/DPAPI/очередь не заменяются этим механизмом.

При смене адресов появляется уведомление о новом сайте и кнопка «Применить после перезапуска». Текущее подключение и загрузки не переводятся на другой сервер в ходе работы. Адреса API, сайта, тарифов и страницы бонусов берутся из одной принятой конфигурации.

## Подготовка защищённой публикации владельцем

1. Создать RSA3072 private key инструментом `tools/VideoGrabber.ClientReleasePublisher`, в защищённой папке вне Git/downloads/API. Сохранить отдельную защищённую резервную копию. Linux private file0600; Windows — текущий владелец и только owner/SYSTEM в DACL. Значения ключей не выводить в логи.
2. Включить только public SubjectPublicKeyInfo PEM в `ClientReleaseTrust.PublicKeys` под постоянным KeyId. Первую программу с этим pin распространить до отключения старого сайта.
3. Собрать из проверенного коммита Setup/ZIP. Сохранить текущий и предыдущий установщики под неизменяемыми версиями в downloads/releases. Получить фактические размеры/SHA-256.
4. Подготовить draft по `ClientReleaseManifest`: product `videograbber`, realm `videograbber-main`, channel `preview`, schema1, строго увеличивающийся sequence, issuedAt/expiresAt до366дней, HTTPS API origin root и website base, версия/URL/байты/SHA-256 установщика, необязательный rollback ниже текущей версии.
5. Проверить и подписать draft офлайн CLI, сначала в новый staging-файл. Проверить сигнатуру клиентским verifier с включённым public pin. Private key не нужен серверу API.
6. После разрешённого выпуска атомарно опубликовать envelope как downloads/client-release.json (`/v1/client-release/preview`) и зеркало `releases/windows/preview.json` в репозитории. Метаданные не содержат токенов/данных аккаунтов.

Резервный анонимный канал помогает при недоступности бывшего домена. Его конфигурация не считается доверенной без подписи. Старый адрес или резервный канал нельзя отключать до распространения первой поддерживающей обновления версии. Подписанный каталог нужно обновить до expiresAt, даже если номер EXE не изменился: подписать новый sequence и срок. Истёкшая конфигурация не должна отправлять авторизационные данные на бывший адрес.

## Будущий переезд на российский сайт

Фактический новый домен пока не задан. До публикации указателя проверить новый HTTPS API/сайт, повторно использовать account_id, базу, auth issuer/audience, session signing и ключи шифрования. Обновить разрешённые OAuth callback URLs и публичные серверные ссылки, Telegram webhook/Mini App и реферальный origin. Это отдельная проверяемая операция переноса; механизм обновлений сам базу не переносит. На другом домене браузеру может потребоваться повторный вход, но не новая регистрация.

Новый каталог сохраняет прежний realm и получает новый sequence. Пользователь подтверждает адрес; применить его следует при следующем запуске. Истёкший/повреждённый cache блокирует новые managed-запросы, сохраняя DPAPI и офлайн-доступ. Валидное обновление того же адреса позволяет повторить восстановление сессии. При восстановлении повреждённого cache подтверждение адреса остаётся явным, подписанный high-water не позволяет вернуть старую конфигурацию.
