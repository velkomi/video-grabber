# VideoGrabber — спецификация персонального Windows-приложения

Дата: 2026-09-06  
Статус: дизайн согласован в диалоге, ожидает финального просмотра перед планированием реализации

## 1. Назначение

VideoGrabber — локальное portable-приложение для Windows, которое скачивает доступное пользователю незашифрованное видео по ссылке, автоматически выбирает подходящий движок, сохраняет материал в максимальном доступном качестве и проверяет полученный файл. В приложение также входит базовый редактор на FFmpeg для обрезки, склейки и извлечения аудио.

Приложение предназначено только для личного использования на компьютере владельца. Оно не использует облачный сервер и не передаёт ссылки, файлы, cookie или историю сторонним сервисам.

## 2. Поддерживаемая среда

- Целевая машина: Windows 10 Enterprise LTSC 2021, версия 21H2, build 19044, x64; также допускается Windows 11 x64.
- Интерфейс: C# 14, .NET 10 и WinUI 3 через стабильный `Microsoft.WindowsAppSDK` 2.4.0.
- Распространение: portable-папка с главным `VideoGrabber.exe` и локальными компонентами.
- Основные внешние движки: `yt-dlp`, `N_m3u8DL-RE`, `FFmpeg`, `FFprobe`.
- Анализ страницы: Microsoft Edge WebView2 SDK 1.0.4191.47. При отсутствии совместимого WebView2 Runtime приложение показывает безопасную инструкцию по установке официального runtime.

Версия .NET SDK фиксируется в `global.json` после установки официального SDK 10.0.x; NuGet-зависимости фиксируются через central package management и lock-файлы. Движки поставляются только из официальных релизов с проверкой контрольных сумм.

Пользователь запускает только `VideoGrabber.exe`. Консольное окно не показывается. Внутренние бинарники находятся в служебной подпапке приложения; приложение само проверяет их наличие и исправность. Один физический EXE без служебных файлов не является требованием, поскольку отдельное хранение FFmpeg и других движков упрощает безопасное обновление и откат.

## 3. Границы продукта

### Входит в первую версию

- Загрузка одиночного видео по URL.
- YouTube, Rutube и остальные сайты, поддерживаемые текущим `yt-dlp`.
- Специализированный адаптер для `1tv.ru`.
- Резервное обнаружение прямых MP4, HLS (`.m3u8`) и DASH (`.mpd`) через WebView2.
- Выбор лучшего качества, заданного разрешения или режима «только аудио».
- MP4, MKV и исходный контейнер.
- Субтитры, обложка и метаданные, когда источник их предоставляет.
- Очередь, отмена, пауза там, где движок допускает безопасное продолжение, и автоматическая докачка после сбоя.
- Базовый редактор: обрезка, разбиение, склейка, извлечение аудио.
- Проверка результата через FFprobe и короткие decode-проверки FFmpeg.
- Понятная классификация ошибок и обезличенный технический журнал.

### Не входит

- Обход DRM, платного доступа, CAPTCHA или технических ограничений платформы.
- Запись экрана.
- Облачная обработка и синхронизация.
- Публикация, загрузка видео обратно на сайты и раздача файлов.
- Полноценный нелинейный видеоредактор с эффектами, титрами, цветокоррекцией и многодорожечным монтажом.
- Гарантия работы буквально с каждым сайтом: поддерживаются доступные незашифрованные медиапотоки, которые разрешено получать в текущей пользовательской сессии.

## 4. Архитектура

Приложение состоит из небольших модулей с отдельными интерфейсами.

1. **Desktop Shell** — WinUI 3, навигация, настройки и связывание интерфейса с сервисами.
2. **Download Orchestrator** — очередь и выбор стратегии анализа/загрузки.
3. **yt-dlp Adapter** — запуск официального `yt-dlp`, разбор JSON и структурированного прогресса.
4. **Site Adapter Host** — изолированные правила сайтов; первым поставляется адаптер `1tv.ru`.
5. **WebView2 Stream Detector** — резервно открывает страницу в локальном профиле и фиксирует только подходящие медиазапросы.
6. **Manifest Downloader** — передаёт HLS/DASH/MSS в `N_m3u8DL-RE`, управляет временными файлами и повторными попытками.
7. **Media Processor** — безопасно вызывает FFmpeg для mux/remux, конвертации, обрезки и склейки.
8. **Media Validator** — использует FFprobe и FFmpeg для проверки контейнера, потоков, длительности и декодирования.
9. **Component Manager** — проверяет установленные версии и предлагает отдельно обновлять движки.
10. **Sanitized Diagnostics** — сохраняет локальный журнал без cookie, заголовков авторизации, токенов и полных URL с чувствительными query-параметрами.

Модули взаимодействуют через типизированные модели задач, найденных потоков, прогресса и ошибок. Командные строки не формируются конкатенацией пользовательского текста: аргументы передаются как отдельные параметры процесса.

## 5. Поток загрузки

1. Пользователь вставляет URL и нажимает «Анализировать».
2. URL нормализуется и проверяется; разрешены только `http` и `https`.
3. Orchestrator сначала запускает подходящий site adapter, если домен поддерживается явно.
4. Затем `yt-dlp` выполняет анализ без скачивания и возвращает метаданные и форматы.
5. Если подходящих форматов нет, WebView2 Stream Detector открывает страницу и ищет медиазапросы MP4/HLS/DASH без выполнения произвольных команд со страницы.
6. Пользователь видит название, длительность, превью и доступные варианты качества.
7. Для обычного файла используется прямое скачивание; для поддерживаемого сайта — `yt-dlp`; для manifest URL — `N_m3u8DL-RE`.
8. Если видео и звук разделены, FFmpeg объединяет их без перекодирования, когда контейнер совместим.
9. Результат записывается сначала во временное имя, проверяется и только затем атомарно переименовывается в итоговый файл.
10. Временные файлы автоматически удаляются только после успешной проверки. При сбое они сохраняются для докачки или восстановления.

Для `1tv.ru` адаптер извлекает идентификатор ролика, обращается к официально используемому страницей playlist endpoint, сравнивает фактические параметры HLS-вариантов и не доверяет качеству, заявленному только в имени MP4-файла.

## 6. Главное окно

Вкладка «Загрузчик» содержит:

- поле «Вставьте ссылку»;
- кнопки «Вставить» и «Анализировать»;
- карточку видео с превью, названием, сайтом и длительностью;
- выбор качества: «Лучшее доступное», 4K, 1080p, 720p и «Только аудио»;
- выбор контейнера: MP4, MKV или исходный;
- переключатели субтитров, обложки и метаданных;
- папку сохранения;
- кнопку «Скачать»;
- очередь со статусом, прогрессом, скоростью, оставшимся временем, отменой и продолжением;
- действия «Открыть файл», «Открыть папку», «Открыть в редакторе» и «Подробности».

Основной сценарий остаётся коротким: вставить ссылку → проанализировать → скачать.

### Визуальный стиль и удобство

- Современный спокойный интерфейс в стиле Windows 11 без визуального шума.
- Светлая и тёмная темы с автоматическим следованием системной настройке.
- Русский язык по умолчанию; технические термины заменяются понятными формулировками.
- Крупная центральная зона для вставки URL и перетаскивания локального файла в редактор.
- Один основной акцентный цвет; самые важные действия выделяются, второстепенные скрываются в меню «Дополнительно».
- Встроенные пустые состояния, skeleton/loading-состояния, понятные предупреждения и действия для восстановления после ошибки.
- Масштабирование Windows 100–200%, поддержка клавиатуры, видимый фокус, достаточный контраст и подписи для accessibility.
- На ширине маленького окна карточки перестраиваются в одну колонку без горизонтальной прокрутки.
- Очередь использует компактные карточки с превью и одной строкой главного статуса; подробные логи не загромождают главный экран.

Навигация состоит из трёх разделов: «Загрузчик», «Редактор» и «Настройки». Частые операции доступны за один-два клика. При первом запуске показывается короткая встроенная подсказка из трёх шагов, которую можно закрыть навсегда.

## 7. Редактор

Вкладка «Редактор» открывает скачанный или произвольный локальный медиафайл. Исходный файл никогда не перезаписывается.

### Операции

- предпросмотр;
- временная шкала с начальным и конечным маркерами;
- обрезка выбранного интервала;
- разбиение на несколько фрагментов;
- список файлов для склейки с изменением порядка;
- извлечение аудиодорожки;
- экспорт в MP4 или MKV.

### Режимы экспорта

- **Быстро, без потери качества** — stream copy. Обрезка выполняется по ближайшим подходящим ключевым кадрам; интерфейс предупреждает о возможном небольшом смещении границы.
- **Точно по кадру** — перекодирование с аппаратным ускорением только после проверки совместимого кодека и устройства; при недоступности используется программное кодирование. Интерфейс показывает, что операция займёт больше времени и изменит видеопоток.

При склейке программа сначала проверяет кодеки, разрешение, частоту кадров, временные базы и параметры аудио. Совместимые файлы объединяются без перекодирования. Несовместимые требуют явного подтверждения перекодирования и выбранного выходного профиля.

После любой операции результат проходит ту же валидацию, что и загруженное видео.

## 8. Работа с авторизацией

По умолчанию приложение не читает профили браузеров и не использует cookie.

Если ресурс доступен только после входа, пользователь может отдельно включить один из режимов:

- открыть страницу во встроенном WebView2 и войти вручную;
- разово разрешить `yt-dlp` использовать cookie выбранного установленного браузера, если это технически поддерживается.

Приложение не отображает, не экспортирует и не пишет cookie в журнал. Локальный WebView2-профиль хранится в каталоге данных приложения и может быть очищен отдельной кнопкой с явным подтверждением. Автоматический вход и хранение паролей самим приложением отсутствуют.

## 9. Ошибки и состояния

Пользовательские ошибки классифицируются как:

- неподдерживаемая или некорректная ссылка;
- видео удалено или недоступно;
- требуется вход;
- географическое ограничение;
- DRM-защита;
- CAPTCHA/антибот-защита;
- поток истёк, требуется повторный анализ;
- сетевой таймаут или разрыв;
- недостаточно места;
- ошибка объединения/перекодирования;
- итоговый файл не прошёл проверку.

Ошибка не маскируется статусом «Готово». В очереди доступны повтор, повторный анализ и просмотр очищенных подробностей. Недостаток места проверяется до начала загрузки по известному или оценочному размеру с безопасным запасом.

## 10. Безопасность и приватность

- Никакой телеметрии и внешней аналитики.
- История хранится локально и может быть отключена.
- URL с токенами и чувствительные заголовки редактируются до записи в лог.
- Любой внешний процесс запускается без shell-интерпретации и получает аргументы отдельным массивом.
- Имена файлов очищаются от запрещённых Windows-символов, зарезервированных имён и попыток выхода из выбранной папки.
- WebView2 Detector принимает только сетевые ответы и метаданные; веб-страница не получает доступ к локальной файловой системе приложения.
- Обновления скачиваются только с allowlist официальных GitHub-репозиториев по HTTPS и устанавливаются после проверки опубликованной контрольной суммы или подписанного артефакта, когда он доступен.
- Обновление никогда не выполняется во время активной загрузки или редактирования.
- Удаление исходников, готовых файлов, истории и профиля авторизации требует отдельного явного действия пользователя.

## 11. Обновления компонентов

Интерфейс приложения и медиадвижки обновляются независимо.

- Проверка обновлений выполняется вручную или не чаще одного раза в сутки при запуске.
- Пользователь видит текущую и доступную версии.
- Перед заменой текущий бинарник сохраняется как локальная резервная копия.
- После замены запускается harmless self-test (`--version` и базовый анализ тестового fixture без загрузки чужого контента).
- При неудаче автоматически восстанавливается предыдущая версия.
- Пользовательские плагины `yt-dlp` по умолчанию отключены; подключение допускается только после отдельного аудита исходного кода.

## 12. Локальные данные

Portable-каталог содержит приложение и движки. Пользовательские данные отделены:

- `data/settings.json` — настройки без секретов;
- `data/jobs.db` — очередь и история;
- `data/logs/` — очищенные журналы с ограничением размера и срока хранения;
- `data/webview/` — отдельный профиль встроенного браузера;
- `cache/` — превью и временные метаданные;
- выбранная пользователем папка — готовые видео;
- выбранная временная папка — фрагменты незавершённых задач.

При первом запуске пользователь выбирает папки для видео и временных данных. Приложение не использует системные каталоги без необходимости.

## 13. Проверки

### Автоматические

- Unit-тесты выбора стратегии, проверки URL, формирования аргументов и редактирования логов.
- Контрактные тесты адаптеров на сохранённых безопасных fixtures без сетевого доступа.
- Integration-тесты процессов `yt-dlp`, `N_m3u8DL-RE`, FFmpeg и FFprobe на небольших локальных медиафайлах.
- Тесты паузы, отмены, повторного запуска и восстановления очереди.
- Тесты fast trim, frame-accurate trim, совместимой и несовместимой склейки.
- Проверки отсутствия секретов в журналах.
- Сборка Release x64 и запуск на чистом профиле пользователя.

### Ручные smoke-тесты

- публичный ролик YouTube;
- публичный ролик Rutube;
- разрешённый ролик `1tv.ru`;
- прямой MP4;
- тестовые HLS и DASH manifests;
- задача после сетевого разрыва;
- файл с раздельными аудио и видео;
- обрезка и склейка;
- корректное объяснение DRM или необходимости входа без утечки данных.

Сетевые тесты используют только публичные тестовые или явно разрешённые материалы. Результат считается успешным только после проверки существования файла, FFprobe и короткого декодирования начала, середины и конца.

## 14. Критерии готовности первой версии

Первая версия готова, когда:

1. На Windows приложение запускается из portable-папки без установки Python.
2. Пользователь может вставить поддерживаемую ссылку, увидеть форматы и скачать выбранный вариант.
3. Проверенные тесты проходят для YouTube, Rutube, `1tv.ru`, прямого MP4, HLS и DASH.
4. Раздельные дорожки корректно объединяются.
5. Незавершённая поддерживаемая задача восстанавливается после перезапуска.
6. Готовый файл не помечается успешным до прохождения проверки.
7. Редактор выполняет обе разновидности обрезки, совместимую склейку и безопасно предлагает перекодирование несовместимых файлов.
8. Исходники и пользовательские файлы не перезаписываются автоматически.
9. Логи не содержат cookie, токенов и заголовков авторизации.
10. DRM, CAPTCHA и другие неподдерживаемые случаи завершаются понятной ошибкой без обхода защиты.

## 15. Этапы реализации

1. Аудит лицензий, релизов и структуры выбранных open-source компонентов.
2. Каркас WinUI 3, модели задач и локальное хранение настроек.
3. Интеграция `yt-dlp`, FFmpeg и FFprobe с безопасным запуском процессов.
4. Очередь, прогресс, отмена, восстановление и проверка файлов.
5. `1tv.ru` adapter и `N_m3u8DL-RE` fallback.
6. WebView2 Stream Detector и отдельный профиль авторизации.
7. Редактор: fast trim, точная обрезка, склейка и извлечение аудио.
8. Component Manager с проверкой происхождения и безопасным откатом.
9. Полный набор тестов, portable-сборка и проверка на целевом компьютере.

Каждый этап должен завершаться тестами и проверяемым артефактом. Публикация, push, установка системных зависимостей и изменение глобальной конфигурации выполняются только после отдельного разрешения пользователя.
